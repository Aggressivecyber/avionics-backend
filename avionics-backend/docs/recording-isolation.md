# 原始记录与分析隔离

FramePipeline 分别运行记录和分析线程。记录线程只负责接收、写入原始归档并将已记录报文交给分析队列。分析异常、分析队列超限或分析收尾输出失败时，分析进入明确失败状态，原始记录继续进行。原始记录失败仍使采集入口拒绝后续输入。

分析失败后保存 `analysis_failure`、`analysis_first_missing`、`analysis_cursor` 和跳过数量。`analysis_cursor` 表示已提交给解码与分析状态的原始报文位置，不能代表参数和结果已经持久化；有状态规则及重排可能仍持有样本。修复配置或输出条件后，应从本次原始归档开头离线重算，重建规则基线。

`accepted` 是入口接收数量，`recorded` 是原始记录器已处理数量，`completed` 是分析已消费数量。`drainSource()` 等待原始记录，不再等待分析。存储缓冲刷新与断电持久性分别定义；这些计数不等同于设备发送量或断电后的可恢复量。

退出码 0 表示当前处理成功，1 表示记录或其他致命执行错误，3 表示原始记录可用但分析未完成。关闭管线时先停止来源、排空原始输入，再关闭分析队列；正常分析最终由消费者的 `finish()` 完成，收尾异常也归入分析状态。

`[pipeline]` 可指定下列预算。条数和字节同时生效，字节采用对象及自有容量的保守计费，正在处理的报文与 SDK 自己的缓冲另计。

| 配置 | 默认值 | 作用 |
| --- | ---: | --- |
| queue_frames | 4096 | 原始输入排队条数 |
| queue_bytes | 67108864 | 原始输入排队字节预算 |
| source_frames | 1024 | 单来源排队条数 |
| source_bytes | 16777216 | 单来源排队字节预算 |
| analysis_frames | 4096 | 分析排队条数 |
| analysis_bytes | 67108864 | 分析排队字节预算 |
| max_sources | 256 | 本会话保留的来源计数状态上限 |

来源预算限制热点来源占用共享队列，拒绝计数分别显示原因。新增来源在启动前预留状态；本会话达到来源历史上限后，新增 ID 在启动前被拒绝，可开启新会话或显式增加预算。重新启动同一 ID 复用其计数状态。预算只定义软件资源边界，支持的真实负载需在目标设备上验收。

`python scripts/verify_analysis_recovery.py --build build-gcc-release` 验证公开命令行中的分析故障、原始数据保留及离线重算。测试数据保存在当前工程的 `runs/` 下。
