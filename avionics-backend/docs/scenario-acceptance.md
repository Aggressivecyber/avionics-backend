# 场景验证与自动验收

入口：插件中心 → 场景验证插件 → 配置场景 → 保存并准备 → 左下角开始采集。
保存只准备来源，尚不产生数据；达到预设帧数后自动结束、封存并验收。配置随项目保存，每次采集单独保留场景、字典和公式快照。

首批场景：正常运行、参数越限、响应超时。一个模拟来源在同一帧内携带温度、指令和反馈，采用独立模拟时钟；原始记录的接收时间仍由主机记录。软件合成数据不对应真实航空器 ICD，也不模拟电气波形或采集卡。

默认4秒、间隔20毫秒，共201帧、603个参数样本。1秒时发出指令；正常温度20 °C，上限25 °C，越限值35 °C。反馈延迟可配置，响应截止时间可配置；反馈恰好到达截止时刻仍为正常。所有数据由时间与场景参数确定，无随机输入。

## 验收依据

C++ 插件生成数据，独立 Python 验收器按 `scenario-contract-v1` 合同检查完整落盘数据。验收不从界面尾部缓存取样。

- 配套字典、规则和两条公式定义一致。
- 帧数完整、无拒绝、归档已封存，文件摘要与封存回执相同。
- 温度、指令、反馈每点的值、时间、质量、序号、原始位置一致。
- 事件种类、数量、时间和指标符合事先定义的预期，无额外事件。
- `温度−上限` 与 `温度>上限` 的每点结果符合独立预期。
- 事件和公式证据可追溯到同一次原始记录。

正常运行预期只有正常响应事件；参数越限预期包含一次越限和正常响应；响应超时预期包含一次超时。预期异常被准确检出属于验收通过。尚未点击开始的准备记录标为“未运行”；开始后提前结束、缺帧、变更配套字典/公式，或计算结果不符，均不得报告通过。

每次完整分析目录写入 `acceptance.json` 和 `acceptance.html`；插件中心可打开最近一次结果，历史记录可查看指定采集的结果。选择检查项后可查看预期、实际结果并打开原始报文。场景验收结论与“已封存”的记录状态分别表达。

## 上限规则

`[limit 名称]` 使用 `input_source`、`input_parameter`、`upper`。首次有效值或连续有效值严格大于上限时发出 `parameter_above_limit`；持续越限不重复发出。连续有效数据恢复至上限或以下时发出 `parameter_within_limit`。无效输入、过期数据或代次切换不生成虚假的恢复事件。该规则也可在项目设置的分析规则中编辑。

## 验证与边界

`AEROBUS-Analysis.exe --scenario-check --output E:/AEROBUS-checks` 在打包版本中执行真实 Qt、插件、后端和分析进程验收。包括固定事件时间和原始十六进制样例、重复运行、鼠标配置、原始证据、项目重开、准备阶段修改、提前停止、边界值，以及对样本/事件/公式的故意篡改测试。

按钮按下75 ms、释放140 ms；导航页面淡入170 ms，插件状态变化170 ms。动作立即执行，动画只影响绘制，不改变按钮布局、命中区域和采集时刻。快速连续切换中止旧动画并显示最后选择的页面。

本轮验收证明软件场景符合所声明合同。真实采集卡/SDK、硬件时序、真实负载和跨设备同步仍需要设备验收；吞吐上限及长时间耐久测试是后续工作。
