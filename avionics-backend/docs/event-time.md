# 事件时间与迟到范围

配置 schema 2 要求显式指定 `[processing] allowed_lateness_ms`。软件使用已配置并有外部依据的时钟映射，按时间组缓冲和排序。输入契约为每个来源参数流有序，跨来源输入的已映射时间偏差不超过声明的迟到范围。时间质量先检查同流序号、顺序和载荷；重复、乱序、序号缺口或无效载荷不能推进重排进展。

每个时间组只释放严格早于 `已观察到的最大可用时间 - 允许迟到范围` 的样本。相同时间仍保留在开放边界内，以来源、参数、采集代次、序号和原始记录编号稳定排序。超出已关闭边界的样本输出 `late_for_group`，不参与正常关联。

声明一个时间组表示这些来源已具有可比较时基。设备重启后的时钟映射必须继续满足该契约；需要重新标定的设备应更新映射并开启新会话。软件不通过来源名称或回调到达时间推断硬件已同步。

`advance(group, watermark)` 只接收调用方已经验证的水位，先处理截至水位的全部缓冲样本，再检查超时。此调用关闭等于水位的时间点，之后到达的同点数据会被标记为迟到。允许响应恰在截止时刻到达，不能先判超时再处理响应。

`finish()` 处理剩余已记录样本；未得到充分结论的关联输出 `response_unresolved`。没有新观测或显式水位时不使用电脑等待时间推断设备超时。没有收到数据的来源不会自动变成健康或已完成；来源空闲与退出的生命周期状态由采集和会话管理负责。

`max_reorder_samples` 限制整个分析会话的重排样本数量，默认 8192。超过预算显式报错；运行会话须记录分析失败与重算位置。未知时钟边界使该来源的缓冲观测带 `unmapped_clock_boundary` 输出，防止边界前的缓冲样本随后恢复旧关联基线。

`config/ground-monitor.example.ini` 是同一宿主模拟时钟的示例，显式设置 50 ms 迟到范围。该值描述此合成示例，不是对真实采集卡的建议指标。schema 1 保持旧版零缓冲语义，以便重算历史配置；该模式要求全局到达时间有序。
