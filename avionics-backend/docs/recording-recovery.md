# 采集分卷与中断恢复 · v0.8

## 操作

在“项目设置 → 项目与目录”点击“设置分卷与容量预警”，进入“字典与规则 → 采集保存”。保存配置后，下一次采集使用该配置。默认按 **256 MiB 或 30 分钟**换卷，任一条件先达到即生效。底部显示当前卷数、所在文件系统的可用空间；低于 **2 GiB** 时持续显示容量预警。预警不删除文件，也不自动停止采集；实际写入失败会进入记录异常状态。

```ini
[recording]
volume_bytes=268435456
volume_seconds=1800
warning_free_bytes=2147483648
```

每个值设为 0 可关闭该条件。大小上限包括文件头、记录和封口，非零值至少 256 字节；单条报文不拆分，超过上限的单条报文单独成卷。时长使用单调时钟，从该卷第一条记录开始计时，达到时长后的下一条记录进入新卷。空闲期间不产生空卷，也不改写采集时间。

第一卷仍是项目记录的 `.avbus` 文件，后续卷追加 `.part000002.avbus`、`.part000003.avbus` 等。分析、回放和报文查看均选择**第一卷**，自动连接后续卷。移动项目时一起移动全部分卷。卷号、会话编号、前一卷摘要和逐条 CRC 会检查缺卷、错序、混入和内容破坏。

打开项目时，后台自动检查未封存、异常或待校验的记录；后台异常退出后也会检查本次记录。历史页显示通过校验的连续记录数量。“检查记录”可再次扫描。检查不会修改原始文件，不把采集完整性与分析完成状态混为一谈。

点击“恢复有效记录”后，程序创建独立的恢复记录，使用原始采集保存的配置、关系定义和试验步骤快照，从第一条有效记录重新计算参数、判据和全部公式，生成历史索引、报告及可导出的 CSV。原始分卷保留，遇到第一处损坏、缺卷或未完成记录即停止，后面的内容不跳过拼接。历史页和报告标记“中断恢复 / 原始采集未完整结束”，恢复数据本身重新封口。恢复副本保留观察到的会话身份与记录号，因此仍可定位原始报文；项目同时记录来源采集和原始路径。

当没有可恢复记录，或保存的配置/关系文件不可用，界面说明错误，不拿当前配置猜测旧采集的含义。恢复工作在独立进程中执行，窗口继续响应；恢复期间不能切换项目或开始新采集，关闭窗口会等待恢复结束。

## 命令行

```text
bus_analyze --check FIRST_VOLUME
bus_analyze --recover FIRST_VOLUME NEW_ARCHIVE
bus_analyze --inspect FIRST_VOLUME
bus_analyze --analyze SAVED_CONFIG FIRST_VOLUME NEW_OUTPUT_DIRECTORY
bus_analyze --record FIRST_VOLUME RECORD_INDEX
```

`--check` 返回 `complete/incomplete`、有效前缀数量、停止文件、当前卷通过检查的字节边界和错误原因。成功输出检查报告的退出码为 0；是否完整须读取 `status`。`--inspect` 继续要求整个卷链有合法终止封口。`--recover` 独占创建新记录并写入 `.recovery.json`，该回执记录**源数据**扫描结果，恢复副本另用 `--inspect` 校验。源文件内容可以不完整而恢复操作成功。恢复输出也按 256 MiB 分卷。

## v3 格式

所有整数小端。每卷头为 60 字节：`AVBUS03\n`、16 字节会话身份、u32 卷号、32 字节前一卷全文件 SHA-256；第一卷的前卷摘要为零。普通记录沿用 v2 的长度/CRC、字段及扩展。

封口为 65 字节：u32 长度 0、u32 CRC32，随后 u64 本卷记录数、u64 本卷封口前字节数、u64 本卷最后记录号、32 字节本卷数据 SHA-256、u8 结束标记（0 正常结束，1 后续还有卷，2 恢复副本结束）。CRC 包含结束标记。只有全部卷顺序、会话、摘要、记录序号和封口一致，才报告 `sealed`。

摘要的 `records`、`data_bytes` 汇总全部卷；`file_sha256` 是按卷顺序串联完整文件字节的 SHA-256，`data_sha256` 串联各卷封口前字节。`volumes` 为通过卷头检查的卷数；`recovered=true` 表示恢复副本。v2 的单文件摘要定义保持不变。恢复副本即使 `integrity=sealed` 也不能当作原始采集完整结束。

记录线程在记录边界检查 1 秒刷新周期，空闲等待也会触发刷新；分卷与正常结束也刷新并检查关闭结果。尚在入口队列、stdio 缓冲中或写到一半的记录可能无法恢复。`fflush` 不提供断电后的介质持久性保证；本版验收为进程强制结束与受控截断，未进行物理断电试验。SHA-256/CRC 用于一致性检查，不是来源认证或数字签名。

## 验收

- C++：大小/时间换卷、完整卷链、逐字节尾部截断、半条记录、缺卷/错序、恢复身份与原文件保留；17 条确定性样本各占一卷，参数、规则结果及证据与不分卷执行逐字节一致。
- Qt：真实子进程采集与强制结束，中文长路径容量预警，重开项目自动检查，通过恢复按钮重建公式、历史与报文证据，导出报告和 CSV，比较原始文件内容保持不变。容量预警通过提高门限触发，未填满物理磁盘。
- 测试入口：`ctest` 的 `archive_integrity`、`processing_integration`、`qt_recording`；独立发行版可用 `AEROBUS-Analysis.exe --recording-check --output E:/验收目录`。

所有测试数据和发布验收保存在 E/D 盘。工程功能不等同于论文创新或真实采集卡验收。
