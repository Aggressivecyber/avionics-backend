# v2 原始记录与结果身份

新写入使用 v2；读取保留 v1。v1 无封存，输出 `legacy_unverified`，会话身份为 `null`。

v2 全部整数为小端：24 字节文件头包含 `AVBUS02\n` 和 16 字节随机会话身份。普通记录保留 v1 的 8 字节长度/CRC32 前缀与 80 字节固定字段，末尾允许 TLV 扩展（u16 类型、u16 长度、内容）。类型 1 为 16 字节原始会话身份；未知可选类型可跳过，类型 0 及未知最高位为 1 的必需类型拒绝读取。记录号必须为正且递增。

成功关闭写入 64 字节封存：u32 长度 0、u32 CRC32，随后 u64 记录数、u64 封存前字节数、u64 最后记录号及 32 字节 SHA-256。摘要覆盖文件头和所有普通记录。全文件 SHA-256 另覆盖封存。读取必须验证数量、长度、记录号、摘要和没有尾随数据，才输出 `sealed`。不写析构自动封存；异常中断的文件保留未封存状态。

SHA-256 用于内容一致性，不是数字签名。封存证明这个文件与写入内容一致，不证明采集卡无丢帧。入口拒绝计数、设备侧计数、时钟质量和会话异常仍需单独判读。`fflush` 和正常关闭已检查；没有承诺断电后的设备介质持久性。

参数及关联证据使用 JSON schema 2，增加采集会话、原始会话、原始记录位置及配置内容 SHA-256。配置从一次二进制读取中解析、计算摘要、保存快照，避免运行中源文件变化造成副本与已解析配置不一致。相同内容和输入产生相同身份，在线与离线结果可逐字节比较。

`bus_analyze --inspect INPUT` 可独立校验归档并输出摘要，不需要参数字典。离线 `summary.json` 的 `status=complete` 表示本次分析完成，`archive.integrity` 单独表示输入封存状态。实时 `.session.json` 同时记录封存、分析状态与入口丢弃数。`--fixture` 固定会话身份以维持测试样本的确定性；真实采集使用系统随机身份。
