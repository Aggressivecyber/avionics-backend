# Qt 地面试验工作台 · v0.4.2

前端采用 Qt Widgets / 官方 Python 绑定 PySide6 6.9.2。界面和 C++ 采集宿主分属两个进程，通过 `QProcess` 的异步信号交换控制与显示数据；采集宿主继续为每个来源创建独立的 SDK 工作进程。界面没有加载设备插件，也不在 Qt 事件线程等待设备启停。

## 本机启动

源码、输出及临时文件保留在 D/E 盘。现有环境为 `D:/anaconda/python.exe`，Qt 版本通过实际创建 `QApplication` 验证为 6.9.2。

```powershell
.\scripts\start-frontend.ps1 -Python D:/anaconda/python.exe -BinDir D:/avionics-builds/ground-backend-v03-final/bin -RuntimeDir C:/msys64/mingw64/bin -DataDir E:/avionics-data/ground-station
```

发布包包含 `Start-AEROBUS.cmd`、界面源码和后端运行库，默认复用上述 D 盘 Python / Qt。可传 `-Python D:/other-env/python.exe -DataDir E:/other-data`。Qt/Python 运行时没有打入本次便携包；依赖版本见 `frontend/requirements.txt`。

## 操作流程

1. 选择字典/规则配置与 D/E 盘数据目录，填写试验名称，点击“新建会话”。原始归档、生命周期日志、配置副本与参数/事件结果使用同一会话名称。
2. 在插件中心点击“启用插件”，只加载配置并进入就绪状态。点击顶部“开始采集”才开始获取数据；该按钮在所有页面始终可见，没有就绪来源或所有来源正在运行时置灰。“停用”停止该插件的来源并保留会话；之后点击“开始采集”不会重新启动已停用插件。点击“查看详情”阅读用途、功能、配置和当前来源状态。监测页也可“添加”采集源，源 ID 与字典中的 `source` 对应。
3. 参数表显示工程量、单位、质量、原始记录索引与来源代次。选择参数查看最近趋势；无效质量样本断开曲线，替换或重启产生新代次时清空旧曲线。
4. 在独立的“数据关联”页勾选参数、命名关系并填写公式。右侧显示结果、映射时间和曲线。双击原始参数或“后端规则事件”查看会话身份、配置摘要与原始记录位置。监测页底部保留参数和操作日志。
5. 点击“结束并封存”，等待后端回执。窗口关闭也先停止来源并等待封存。采集降级、记录失败和分析不完整分别显示；已有 SDK 故障不会因为移除来源而显示成成功采集。
6. 在“离线分析”选择归档，先校验完整性或直接执行重新分析。新输出目录必须不存在。完整性错误显示失败，并清除之前的成功结果。离线分析期间窗口继续响应，结束后可以关闭。

在“合成演示插件”卡片点击“启用插件”，程序自动选择演示字典、新建会话、加载配置 `sensor_a`、`sensor_b`、`control`、`feedback` 四个模拟源并进入监测；此时帧数为零，点击“开始采集”后才生成演示数据。演示没有单独页面。停用后可在同一会话再次启用，但仍需手动点击“开始采集”；其他插件的来源继续运行。归档回放也遵循相同的两步操作。已有其他试验会话时，先封存该会话再启用演示，避免替换正在使用的字典。桌面演示使用 `desktop-demo.ini`，显式允许 20 ms 的到达乱序；原始采集时间保持不变，跨来源仍按实际映射时间和用户设定的对齐窗口计算。

## 自定义数据关联

左侧列表是已解码参数序列，包含来源、单位、质量、映射时间和原始记录索引。勾选多个参数后，界面分配 `A`、`B`、`C` 等别名，中间填写关系名称、公式、输出单位和时间对齐窗口，点击“创建并显示关系”。例如 `A-B` 为差值，`A/B` 为比值，`A+B>C` 为三路条件，`abs(A-B)<=0.25` 为容差判断。公式只引用实际使用的输入；修改左侧勾选不会改变已经创建的关系映射。

右侧展示已命名关系、最近有效值、当前计算状态和对应的相对时间。等待输入时保留最近有效值及其时间，不生成新的有效点。选择关系后显示其曲线与时基；数值关系显示计算值，条件关系以 false=0、true=1 绘图。每条关系保留最近 512 个结果点，最多创建 32 条关系。输出单位由用户填写，公式不自动推导量纲。

输入必须质量有效、属于同一映射时基、考虑时钟不确定性后仍在用户指定的对齐窗口内，并符合参数字典的有效时间。质量失败、除零、显示数据缺口和来源重启会产生明确状态或曲线断点；孤立的有效点也会绘出标记，重启不会沿用旧代次的输入。

关系定义自动保存到所选数据目录的 `relations.json`，重新打开窗口会加载名称、公式和变量映射。新会话清空实时曲线并等待新输入；曲线历史保留在当前窗口，后端原始归档与参数 JSONL 按会话保存。

## 插件说明

插件名称、功能、参数和演示来源配置位于 `frontend/ground_station/plugins.json`。新插件可登记同样的说明字段并放入运行目录。界面读取说明文件，设备动态库仍由独立采集进程加载。当前会话中未登记的自定义插件也会显示卡片，并明确标记功能尚未登记。

## 界面规范

本轮采用 `design-taste-frontend` 的应用界面规范，方向为 Framed sheet，seed `1434715506`，无重抽。浅色 L 形框架与白色工作区形成一层分隔，保留中文字体；字号为 12/14/16/22/28 px，记录帧数使用 32 px。配色、控件样式及曲线颜色统一在 `theme.py`。表格取消隔行底色和表头色带，数值与数值表头右对齐，微软雅黑 UI 的数字等宽经 Qt 字体度量确认。总线分支标记为本项目绘制的 SVG。

顶部操作栏固定保留试验名称、真实会话状态、“开始采集”和“结束并封存”。字典、规则与数据目录集中在“试验配置”弹窗，会话期间可查看；原有修改限制保留。监测指标改为一个分组条；数据关联改为左侧参数与公式上下排列、右侧关系和曲线，减少三栏对数据的挤压。曲线仅在孤立有效点上绘制点标记，数据缺口仍断开。

各页先回答一个操作问题：插件中心回答哪些插件已经就绪；监测页回答哪些来源正在采集、数据是否完整；数据关联回答所选参数的关系如何随时间变化；离线页回答归档是否完整、重新分析得到什么结果。展示的数据继续来自后端和公式引擎，没有新增展示用的业务统计。

Qt 桌面保留 1160×780 的最小窗口。本轮在 1160×780、1440×900、1920×1080 三档截图并检查按钮边界、输入区域交叠和实际字体。skill 的 CSS 静态检查应用于原样导出的 Qt 样式；浏览器 DOM 检查及手机网页检查不适用于原生 Qt，不计作已通过。

## 显示与记录边界

- 显示刷新间隔 250 ms。每次最多返回最近 512 个参数样本、128 个关联事件，并通过游标报告界面没有取得的历史条数。界面保留 512 个趋势点、4096 个参数状态、200 个事件和 300 行操作日志。
- 显示缓冲覆盖只影响界面历史，不影响完整的参数/事件 JSONL 或原始归档。显示历史计数与采集拒绝计数分开呈现。离线结果也只读取有界文件末尾。
- 两秒没有新状态会显示“等待后端响应”；命令没有通过就显示错误。后端异常退出且没有封存回执时，界面不确认记录完整。
- 趋势显示采用通过质量检查的映射事件时间。界面不会生成设备时间水位、自动推断硬件同步或补造规则结果。
- 关闭界面期间等待后端排空和封存。若外部强制结束后端，原始文件可能未封存，完整性校验会拒绝该文件。

## 控制协议 1

启动：`bus_backend --control NEW_ARCHIVE CONFIG_INI`。命令行在 Windows 从 UTF-16 转成 UTF-8；控制管道使用 UTF-8。

标准输入每行一条命令。请求编号为正整数，字符串使用 C++ `std::quoted` 的双引号及反斜杠转义，禁止内嵌换行。控制行上限 64 KiB。处理后只向标准输出写一条紧凑 JSON，诊断使用标准错误。

```text
1 add "sensor_a" "E:/plugins/含 空格的插件.dll" "period_ms=20"
2 start "sensor_a"
3 snapshot 0 0
4 stop "sensor_a"
5 replace "sensor_a" "E:/plugins/new.dll" "period_ms=20"
6 remove "sensor_a"
7 quit
```

启动时发送 `{"schema":1,"type":"ready",...}`。普通响应包含 `request`、`ok`，以及成功时的 `data` 或失败时的 `error`。`snapshot` 的两个参数为已经取得的样本和事件游标；响应包含记录/分析状态、来源状态、增量参数/事件和新的游标。来源操作在完整解析参数之后执行。

`quit` 的命令响应只表示接受结束请求。只有收到 `type=closed` 的最终会话结果，并且后端正常结束，才能判断记录封存及采集/分析状态。标准输入关闭也会走后端正常排空流程。

## 自动化验收

```powershell
$env:QT_QPA_PLATFORM = 'offscreen'
$env:PYTHONDONTWRITEBYTECODE = '1'
$env:TEMP = 'E:/avionics-data/qt-test-temp'
$env:TMP = $env:TEMP
$env:PATH = 'C:/msys64/mingw64/bin;' + $env:PATH
D:/anaconda/python.exe -B frontend/test_frontend.py --bin-dir D:/avionics-builds/ground-backend-v03-final/bin --output E:/avionics-ui/verification
```

每次测试创建新的 `run-*` 目录，保留 `receipt.json` 和插件、详情、关联等实际 Qt 窗口截图，另存三档尺寸下的四个主页面。Windows 的 offscreen 插件没有系统字体数据库；测试显式读取已经安装的微软雅黑和 Segoe UI 字体。实际桌面程序使用 Windows 平台插件的字体系统。

五组 Qt 界面测试验证：

1. 四源实时显示、显示缓冲覆盖与可见缺口、带中文及空格路径的插件替换、源启停/移除、记录封存、在线与离线参数/事件文件 SHA-256 完全一致、损坏归档拒绝。
2. SDK 加载卡死约五秒期间的 Qt 计时器响应、异步 SDK 故障可见、最终采集降级与原始记录封存。
3. 关闭活动窗口时正常封存、输入源 ID 校验、后端启动失败与 D/E 写入边界。
4. 后端异常退出不会显示成成功封存，未封存的原始文件被完整性校验拒绝。
5. 所有页面保留“开始采集”按钮；启用演示或回放后帧数保持为零，点击该按钮才开始采集；重新启用仍不自动开始；全局开始不会重新启动已停用插件；停用演示后其他插件继续记录；二路与三路命名关系、条件绘图、保存与重新载入。

也可纳入 CTest：配置 `-DAVIONICS_TEST_QT_FRONTEND=ON -DPython3_EXECUTABLE=D:/anaconda/python.exe`，随后运行常规 `ctest --test-dir BUILD --output-on-failure`。另外八项关系计算测试覆盖多变量表达式、公式执行边界、时基、质量、有效时间、时钟不确定性、除零、代次变化和缓冲上限。现有五组 C++ 测试继续执行。Qt 测试结果只证明上述软件场景；设备通道数、连续运行时长、峰值吞吐和真实驱动故障需要在选型后验收。
