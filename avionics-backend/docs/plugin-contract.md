# 插件开发约定 · ABI 2

项目尚未上线，统一重做旧插件，仅接受 `BUS_ABI_VERSION=2` 和准确的结构大小。入口为 `include/plugin_api/bus_plugin.h`；`plugin_support.hpp` 是插件内部可选 C++ 辅助实现。

每个插件导出 `bus_plugin_query`，提供 create/configure/start/stop/destroy/status/last_error。公共边界只有 C 结构、字节、整数和借用指针。异常由插件捕获，用返回值和 `BusError` 传递，禁止让 C++ 异常或 STL 对象跨动态库边界。

## 生命周期

- create 复制宿主函数表，不能启动回调；configure 仅校验参数，不提前占用需要交接的独占设备。
- start 分配设备资源并启动工作；部分启动失败仍须可 stop/destroy。
- stop 可重复调用，须等待工作线程和 SDK 回调退出，释放独占设备。返回后不得继续回调。
- destroy 由创建对象的插件执行，支持部分初始化状态。
- status 与采集并发，使用插件内部同步。last_error 必须保留异步工作错误的具体原因，直到下一次成功启动或对象销毁。

宿主把所有这些调用放在独立工作进程，默认普通命令截止为 5000 ms、停止截止为 1000 ms；超时终止该进程并记录原因。可在字典配置中通过 `[capture] command_timeout_ms`、`stop_timeout_ms` 设为 1..600000 ms。超时值需随实际 SDK 初始化和停止行为验收。

同一实例的管理操作串行，状态查询与采集工作并发。不同来源位于不同进程，不共享进程内全局设备对象；厂商 SDK 是否允许多个物理设备实例仍需实测。设备内核驱动不在用户态隔离范围内。

## 报文与计数

回调中的结构、payload、origin_source 只需在调用期间有效，工作进程复制其内容。单帧载荷上限 65536 字节，原来源字符串上限 128 字节。使用 UTF-8 字符串，协议与时钟编号集中分配。

采集进程回调返回 1 表示成功复制到有界 IPC 传输；宿主接收后还有独立原始入口预算。因此插件 emitted 不等于宿主 accepted，更不等于 recorded。验收同时核对设备侧、传输侧、宿主拒绝和记录计数。IPC 满时产生背压，SDK 是否允许回调等待以及设备缓存能否承受，必须随设备负载测试。

普通来源不填写 origin 字段。回放保留最初的会话身份、来源、代次和记录号；本次录制使用新的会话身份。采集硬件时间不冒充宿主时基，应用层源时间由对应 ICD 和解码器明确定义。

插件 stdout/stderr 归入诊断输出，不混入二进制通道。SDK 工作线程异常需同时增加 errors 并保存 last_error；计数无原因不满足接入验收。

## 接入与升级

1. 在 `plugins/<vendor_bus>/` 实现设备类和 ABI 2 函数表，SDK 仅链接到该目标。
2. 约定协议、通道、硬件状态和时间语义，保留 ICD 所需原始字节。
3. 通过参数接口提供相应解码器，业务规则使用配置而不写入设备插件。
4. 验证启动、断连、错误原因、停止、进程退出、替换回滚、过载与回放。
5. 发布使用独立目录，插件使用已验证二进制及对应 SDK；未通过设备侧计数和时钟测试前不宣称无丢失或跨源实时判定。
