# 插件开发约定（ABI v1）

公共入口为 `include/plugin_api/bus_plugin.h`，C++ 插件实现辅助工具在 `plugin_support.hpp`。辅助工具不是公共二进制接口的一部分。

## 导出与兼容

每个插件仅需提供 `bus_plugin_query(requested_abi, output)` 入口，返回名称、版本、结构大小以及 create/configure/start/stop/destroy/status 函数表。调用方预先填写 output 的 struct_size；版本不匹配或空间不足时返回 0。

所有函数使用声明中的 `BUS_CALL` 调用约定。插件和宿主必须面向同一操作系统、位宽、体系结构与可兼容 C ABI。当前实测组合为 Windows x64 / g++ 15.2。头文件兼容 C 不代表跨任意运行库或系统可直接共享动态库。

插件必须捕获所有 C++ 异常，失败用返回值和调用方分配的 BusError 表达。C++ 字符串、容器和虚函数表不跨动态库边界。模块由宿主管理，设备对象由创建它的插件销毁。

## 生命周期与线程契约

- create 复制 BusHost 函数表，可以保存 context；此阶段不得启动采集回调。
- configure 接收 UTF-8 配置字符串，只在停止状态调用；建议不获取独占设备资源。
- start 完成设备准备并启动采集；失败返回前允许存在部分工作，但后续 stop 必须可以清理。
- stop 可重复调用，必须等待所有工作线程、SDK 异步回调及 host 回调退出，并释放需要交接的独占资源。返回后不得再发出回调。
- destroy 在停止后调用，同时应支持部分初始化失败的对象。
- status 与采集工作线程并发，返回自身同步保护下的计数与运行状态。
- 管理线程不在 emit_frame 回调内部调用 stop/destroy；停止函数不得尝试 join 自己。

宿主串行调用同一实例的管理接口。不同实例可以并行运行，所以插件不能用无保护的全局可变状态存放实例配置。若厂商 SDK 不支持多实例或并发，应在插件内部处理并明确限制。

插件违反 stop 契约时，宿主无法安全卸载正在执行的代码。首版不提供驱动崩溃隔离或强制线程终止。

## 报文约定

emit_frame 中的 BusFrameView、payload 和 origin_source 都是借用内存，只需在调用期间有效。宿主检查大小并复制后返回；返回 1 只说明进入宿主队列，0 表示未被接纳。不得把接纳计数解释为落盘完成。

单帧载荷上限为 65536 字节，来源溯源字符串最多 128 字节。协议编号与时钟域编号需要集中分配，当前仅定义模拟协议和宿主/回放时钟域。实际总线的错误状态与帧元数据必须制定正式映射，不应把所有状态压缩成一个业务数值。

BusFrameView 没有通用传感器测量时间字段；真实设备应保留应用层源时间信息并在解码后明确语义。采集硬件时间不能直接冒充宿主单调时间。

## 添加新插件

1. 在 `plugins/<vendor_bus>/` 添加实现，参考模拟插件的实例类与函数表包装。
2. 在 CMake 中调用 `add_bus_plugin`，将采集卡 SDK 限定在该插件目标内部。
3. 使用已分配的协议编号输出原始报文，不在设备插件内写死平台业务规则。
4. 实现对应 `IParameterDecoder` 并注册到 `DecoderRegistry`。真实参数含义来自设备 ICD。
5. 验证接入错误、拔出/断连、停止、连续替换、回调退出、队列过载、SDK 错误计数和记录回放。

升级时使用新的动态库文件名。两个版本可以在替换准备阶段并存；同一版本的其他实例继续持有自己的模块引用。
